# Long-context retrieval vs the layer 18–22 hypothesis (2026-09-24)

## The hypothesis

The checkpoint gives routed experts their fewest bits (K=2) on layers 18–22 (README "K"
row, `files/exl3_k_map.json`). In DeepSeek-V4.1's encoder/decoder design, every decoder
layer's long-range KV and the indexer's candidate pool are projected from the stream
leaving the encoder (layers 18–19). If the quantizer's allocation hurt anything, it
should hurt long-context retrieval most, and the paper itself calls that area fragile.
The 09-23 paper review proposed a needle / multi-hop test at 64K–300K. Upstream's single
1.03M needle does not settle it: one needle is the easy case.

## Setup

- **Harness:** `scripts/needle_layers.py`, sequential (concurrency 1), direct to
  `192.168.1.97:8000`, 17:34–18:11 CEST.
  - The teacher was otherwise idle.
  - The repl keepalive timer was paused for the run, because a keepalive beside a
    long prefill is the documented unaccounted concurrency source
    (`exl3-moe-barrier.md`).
- **Haystack:** 1.3 MB of real technical prose, repl's `docs/` at `c345029`, sha256
  `aee7ad8e…`. 3.44 chars/token by `/tokenize`. Cut to 8K (the control), 64K, 128K,
  256K and 300K tokens. The max model length is 393,216.
- **Facts per haystack:** 39, each inserted as its own paragraph.
  - 5 key/value needles, "The access code for strongbox Kestrel-17 is 482913.", at depths
    5/25/50/75/95 %. Each has a near-miss decoy key (Kestrel-71 → another code) at a
    random depth, plus 10 unrelated strongbox codes.
  - 3 two-hop chains: "Cabinet Heron-52 opens with the code filed in pigeonhole
    Maple-9." and "Pigeonhole Maple-9 holds the code 731904.", with the hops at
    (10 %, 85 %), (80 %, 15 %) and (40 %, 60 %). Each chain has a near-miss decoy
    pigeonhole, plus 5 unrelated cabinet → pigeonhole chains.
  - The nouns and values never occur in the prose.
- **Questions:** appended after the shared haystack, so the prefix cache serves every
  question after the first.
  - Thinking OFF, greedy: all 8 questions.
  - Thinking ON (effort 75, temperature 1.0): the 3 hop questions again.
- **Grading:** exact 6-digit match. A miss is classified from the document as `decoy`
  (a value it states) or `invented`.
- **Raw data:** `_repl_measurement_stash/needle-layers-20260924/` (`rows.jsonl`,
  `run.log`, the corpus). The run is deterministic (seed 0); rebuilding the facts
  reproduces every answer key.

## Result

| length | single, think off | two-hop, think off | two-hop, think on |
|---:|---:|---:|---:|
| 8K (control) | 5/5 | 1/3 | 3/3 |
| 64K | 5/5 | 0/3 | 3/3 |
| 128K | 5/5 | 0/3 | 3/3 |
| 256K | 5/5 | 1/3 | 3/3 |
| 300K | 5/5 | 0/3 | 3/3 |

- **Exact-key retrieval does not degrade with length.** 25/25 correct at every depth up
  to 300K. None of the answers took the near-miss decoy key (Kestrel-71 for Kestrel-17).
- **Two-hop with thinking is intact at every length:** 15/15.
- **Two-hop without thinking fails at every length, the 8K control included:** 2/15.
  Every miss is classified:
  - 11 of 12 `decoy` answers are *another chain's* pigeonhole code. The model grabs a
    "pigeonhole … holds the code N" line without resolving which pigeonhole.
  - 1 is a strongbox code.
  - The 300K `no_answer` replied with the intermediate pigeonhole name (`Rowan-73`),
    i.e. it stopped after one hop.
  - None took the near-miss decoy of the right chain. This is a thinking-off limitation
    of the task, flat from 8K to 300K, not a long-context effect.
- **Prefill:** flat at 730–775 tok/s from 64K to 300K (300K cold: 407 s). No stall or
  crawl during the run.

## What it decides

The layer 18–22 hypothesis is **not supported** at 64K–300K. On this stack, long-context
retrieval is as good at 300K as in the 8K control. That holds for exact keys among
near-miss decoys and for two-hop chains resolved with thinking. No re-quantization is
indicated.

**Caveats:**
- This is an absolute test. There is no full-precision reference, such as the
  DeepSeek API, on the same prompts. So a weakness present at all lengths (thinking-off
  two-hop) cannot be attributed to, or cleared of, quantization. It can only be shown
  not to grow with length.
- One haystack per length and 3 chains per length are enough to see a length trend, not
  to resolve a few points of accuracy.
- Beyond 300K is untested; the live max model length is 393,216.
